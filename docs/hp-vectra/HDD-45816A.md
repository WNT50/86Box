# HP 45816A / 45817A 硬盘子系统 —— 调查记录与现状

**结论先写**：这块卡**做不了 LLE，也做不了忠实的 HLE**——它的磁盘 BIOS 全在卡上的 6 KB 选项 ROM 里，而该 ROM 没有任何公开 dump，系统 ROM 里也没有替它兜底的代码。下面是把这件事查实的证据，以及一条「用标准 AT 总线卡顶替」的可行路径（已跑通到分区）。

---

## 1. 卡本身的规格（手册第 9 章 + I/O 映射表）

| 项 | 值 | 出处 |
|---|---|---|
| 控制器 | **6809 智能子系统**，接管全部磁盘操作 | `v1_hw.txt` 11134「Hard Disc Subsystem」 |
| 插槽 | **槽 7**（唯一的 16 位槽） | 同上 |
| 主机接口 | **两个寄存器**：控制（写）/ 状态（读）+ 双向 FIFO 数据口 | 同上「Registers」 |
| I/O 地址 | **`1F0h`** 或 **`320h`**（SW1 跳线二选一） | Table 9.5，`v1_hw.txt` 11287 |
| 内存 | **8 KB**：前 6 KB ROM（磁盘 BIOS）+ 后 2 KB RAM（$C0000–$DF000 由 SW1–SW4 选，出厂 `C8000`） | 同上「Memory」 |
| 中断 | **IRQ14 → INT `76h`**，向量表项在 `0000:01D8` | I/O 映射表 `v1_hw.txt` 1966 |
| 软件接口 | 卡 ROM 钩 **INT 13h**（"interfaces with the system at software interrupt 13 BIOS level"） | 同上 |

关键摘句：

> *"The controller-to-system hardware interface is performed by programmable I/O. It interfaces with the system at software interrupt 13 BIOS level."*
>
> *"The status register ... Two of the bits indicate the protocol phase of the controller. ... The data register is bidirectional and passes not only data, but command and status information also."*

**「协议相位」的两个状态位、命令字节表，手册里一个都没给。** 这正是 ROM 里的东西。

## 2. 系统 ROM 里没有硬盘驱动（静态验证）

`vectra45925_64k_combined.bin`（64 KB，`F0000–FFFFF`）逐项扫描：

| 检查 | 结果 |
|---|---|
| `mov dx,1F0h` / `1F1h` / `320h` / `321h` 立即数 | **0 处** |
| `int 76h`（`CD 76`） | **0 处** |
| INT 13h 向量安装（`C7 06 4C 00`） | 0 处（BIOS 用跳转表方式绕开，实际入口 `F000:EC59`） |
| `F000:AA50` 起的 INT 13h 分发表 | 只有软驱 AH=0/2/3/4/5 与复位；`0x8F/0x90` 是驱动器数/类型表 |
| 选项 ROM 扫描 | 有（`C8000` 起按 2 KB 步长找 `55AA`） |
| **INT 13h 功能分发表 `F000:AA60`** | **只有 AH=0/1/2/3/4/5**（复位、状态、读、写、校验、格式化轨）；**AH≥6 全部指向 `F000:AA90`**，那里写 `0040:0041 = 01h`（invalid function）并置进位 |
| 固定盘相关字符串 | `Fixed Disk` / `Hard Disk` / `1701` / `1780` 全部**不存在**（只有 `Diskette`）|

**空机启动后实测**：`INT 41h`（硬盘参数表）= `0000:0000`，`INT 46h` = `0000:0000`，`0040:0075`（硬盘数）= **0**，`in 1F0h/1F1h` = `FFh`。

→ 没有卡就没有任何硬盘支持；卡上没有 ROM 就没有 INT 13h。**没有第三条路。**

## 4. 可行的替代路径（已跑通到分区）

用 86Box 现成的 **AT 总线 XT-IDE 卡**（`hdc_1 = xtide_at`，板载 XT-IDE Universal BIOS r631）给 Vectra 加一块「外来」硬盘卡。它不是 45816A，但证明了这台机器的总线、BIOS、DOS 侧都能正常吃硬盘。

配置（`~/documents/86box/vectra-hdd/86box.cfg`）：

```ini
[Storage controllers]
hdc_1 = xtide_at

[Hard disks]
hdd_01_fn = hdd20.img
hdd_01_ide_channel = 0:0
hdd_01_parameters = 17, 4, 615, 0, ide
hdd_01_speed = 1989_3500rpm
```

实测：

| 项 | 结果 |
|---|---|
| 选项 ROM 落位 | `C8000`（`55AA` 签名扫到） |
| POST 硬盘数 `0040:0075` | **1** |
| XT-IDE 自检输出 | `Master at 1F0h: 86B_HD00` / `-=XTIDE Universal BIOS (AT)=- @ C800h` |
| HP FDISK 3.5（DOS 3.10 B 盘） | 正常启动，建分区成功：`Partition 1  A  DOS  0–614  615 柱面` |
| 镜像 MBR（`hdd20.img` 主机侧核对） | `55AA` ✓；分区项：可引导 `80h`、类型 `01h`（FAT12）、起始 LBA `17`、`41803` 扇区 ≈ 20.4 MB |

**卡住的地方**：建好分区后 XT-IDE BIOS 抢先引导 C:，而 C: 尚未 FORMAT，于是停在 `Missing operating system` / `Invalid partition table`，回不到 `A>` 去执行 `FORMAT C: /S`。已试过开机连按 F8（跳过 ROM 引导），按键到达时引导已完成，无效。

下一步三条候选：

1. **主机侧造 FAT12 分区**：把 DOS 3.10 的 `IO.SYS`/`MSDOS.SYS`/`COMMAND.COM` 直接写进镜像（BPB 手写，启动代码取 A 盘引导扇区 `0x3E` 起那段），然后由 XT-IDE 正常引导 C:；
2. **临时摘掉控制器**做 FORMAT：`hdc_1 = none` 时 DOS 看不到 C:，不可行；
3. **改 XT-IDE 的 ROM 引导行为**：它的 r631 配置存在闪存里，86Box 的 `hdc_xtide.c` 有 `ide_at` 变量可选（`xtide_at` 用 `ide_at.bin`），换一个默认不抢占引导的变体试验。

## 5. 若要真做 45816A 的 HLE，需要做什么

1. 端口 `1F0h`/`1F1h`（或 `320h`/`321h`）的控制/状态 + FIFO 模型；
2. **协议**：相位位、命令字节、块传输格式 —— 无 ROM 无文档，**只能自己定义**，等于自造一套接口；
3. 一段 8086 选项 ROM（`C8000`，6 KB 以内）实现 INT 13h、AH=0/1/2/3/4/5/8/15，走上面自造的协议；
4. IRQ14（INT `76h`）通路。

工作量集中在第 3 项（手写汇编 + 组装成 bin + 挂进 86Box 的 rom 加载路径）。**它跑起来之后，行为和真卡的兼容性无法验证**（没有真卡、没有真 ROM、没有针对这块卡的软件）。

## 7. HP SETUP 程序（Configuration Setup Program Ver 3.2）

**它不在 ROM 里**：系统 ROM 只有一句 `Invalid configuration information - Run SETUP program`（`ROM 0x753`），真正的 SETUP 是 DOS 盘上的 `A:\SETUP.COM`（HP 版，Phoenix 授权，Ver 3.2）。截图见 `setup/`。

### 7.1 主菜单

```
Options Available:

1. Set System Configuration
     Date, Time, Memory Size,
     Internal Disc Drive Types,
     Primary Display Characteristics
2. Align Touchscreen
3. Prepare Internal Hard Disc for Moving
4. Initialize Internal Hard Disc
5. Exit

WARNING: INVALID CONFIGURATIONS HAVE BEEN FOUND, RUN OPTION 1.
Enter option number:
```

**整个系统里唯一提到内置盘类型的地方就是这段菜单文字**（"Internal Disc Drive Types"）。选项 3 是把磁头归位以便搬动，选项 4 是低级初始化 —— 这两个都必须有能应答的硬盘控制器，也就是 45816A 的 ROM。

### 7.2 选项 1 的实际流程（逐页实测）

| 页 | 内容 |
|---|---|
| 1 | 说明：配置存进电池备份内存，首次安装/改时间/增减内存·软驱·显示器时必须跑 |
| 2 | `Configuration Errors Found:` 列出六项：`CLOCK CHIP LOST POWER` / `CONFIGURATION RECORD BAD` / `INCORRECT CONFIGURATION INFORMATION` / `MEMORY SIZE MISCOMPARE` / `DISK C: FAILED INITIALIZATION` / `TIME OR DATE INVALID` |
| 3 | 日期时间确认：`The date is: 00/00/1900` / `The time is: 00:00:00` / `Are the above settings correct (Y or N <Enter>)?` |
| 4 | **系统配置页**（见下） |
| 5 | `Your system must now be restarted. Insert the DOS disc into drive A: and press <Enter>.` |

系统配置页（无硬盘时，与**挂 20 MB XT-IDE 盘时完全相同**）：

```
Flexible Disc Drive A:   360K (Kilobytes)
Flexible Disc Drive B:   360K (Kilobytes)
System Base Memory:      636K
  (System reports 640K installed and reserves at least 4K)
Expansion Memory:        0K (NONE)
Primary Display:         HP Multimode Monochrome or Color (80 column)
360K drives have a "*" on the front cover
Are the above settings correct (Y or N <Enter>)?
```

**注意：这一页没有硬盘行。** 即使挂了一块可用的 20 MB 盘（XT-IDE，INT 13h 正常、`40:75 = 1`），SETUP 也不会多出硬盘条目 —— 说明硬盘的「类型」不是从这里配，而是 NVR 里那笔由选项 1 摘要文字提到的 `Internal Disc Drive Types` 记录的。

### 7.3 `DISK C: FAILED INITIALIZATION` 到底是什么

- **NVR 空白时必然出现**；只要跑过一次 SETUP 存好配置，冷启动就不再报（错误页整页消失）。
- 挂与不挂硬盘，结果一样。
- 所以这条是 **SETUP 依据 NVR 记录做的自检**（记录里的盘类型与实际不符/未设），不是对 45816A 的实时探测。

### 7.4 对建模的含义

SETUP 程序本身不碰端口，它只读写 NVR + 调 INT 13h。要让它真正列出内部盘类型、让选项 3/4 可用，**必须有能应答 INT 13h 的卡 ROM**。这再次指向同一结论：45816A 的固件是绕不过去的。

## 8. `DISK C: FAILED INITIALIZATION` 的真正来源（反汇编）

**不是 NVR 记录比对，是 POST 里一段固定的硬盘自检失败。** 字符串本身在 `SETUP.COM` 里，但它对应的状态码由 ROM 的 POST 产生。

### 8.1 代码路径（`F000:15F5`–`F000:1675`）

```
f15f5: b8 40 00        mov  ax,0x40
f15f8: 8e d8           mov  ds,ax
f15fa: c6 06 75 00 00  mov  byte [0075],0     ; 0040:0075 硬盘数清零
f15ff: 8c c3           mov  bx,es             ; 选项 ROM 段
f160a: … 26 c7 46 00 03 00 / 26 89 5e 02      ; 在栈上拼 far call
f1614: 26 ff 5e 00     lcall *es:0            ; → 调 ROM 的 init 入口（偏移 3）
f1618: fa              cli
f1619: 72 4a           jb   0xf1665            ; init 返回进位 → 0x81xx
f161b: 0e / 1f         push cs / pop es        ; ES = CS
f161d: 33 db           xor  bx,bx
f161f: b4 03 b0 01     mov  ah,3 / al,1        ; INT 13h AH=3：写 1 个扇区
f1623: b5 00 b1 01     mov  ch,0 / cl,1        ; 柱面 0、扇区 1
f1627: b6 00 b2 80     mov  dh,0 / dl,80h      ; 磁头 0、驱动器 C:
f162b: cd 13           int  13h
f162d: 72 31           jb   0xf1660            ; 写失败 → 0x8200
f162f: b8 00 02 8e c0  mov  ax,0x200 / mov es,ax
f1637: b4 02 b0 01 …   mov  ah,2 / al,1        ; INT 13h AH=2：读回同一扇区到 2000:0000
f1643: cd 13           int  13h
f1645: 72 19           jb   0xf1660
f1647: fc 0e 1f 33 f6  cld / push cs / pop ds / xor si,si
f1652: b9 00 01 f3 a7  mov cx,0x100 / repz cmpsw  ; 与 F000:0000 的 512 字节逐字比较
f1659: 75 05           jne  0xf1660
f165b: b8 00 00        mov  ax,0                 ; 通过
f1660: b8 00 82        mov  ax,0x8200           ; ← 失败码：82 = 硬盘类，00 = 驱动器 0
f1665: 8a c4 32 e4 05 00 81  ; ROM init 失败 → 0x8100 + AH
```

一句话：**POST 对驱动器 `80h` 做一次「写一个扇区 → 读回 → 与源数据逐字比较」的自检，任何一步进位或比较不等就返回 `AX = 8200h`**，SETUP 把 `82` 这一级解释成 `DISK C: FAILED INITIALIZATION`。

### 8.2 实测三组

| 场景 | 结果 |
|---|---|
| 无卡（纯 AT 寄存器卡 `ide_isa`） | INT 13h 对 `AH=3` 直接走「无效功能」出口（`F000:AA90`，`40:41 = 01h`）→ 立刻失败 |
| 挂 XT-IDE + 20 MB 空盘 | 报错照旧；启动后主机侧检查镜像**扇区 1 仍全是 `00`** → 那次写根本没落地 |
| 挂 XT-IDE + 已分区 20 MB 盘 | 报错照旧；镜像 `扇区 0` 的 DOS MBR 完好，也说明写没有执行 |

**NVR 对比**：有盘 / 无盘两次冷启动写出的 64 字节 NVR **完全相同**（逐字节 diff 为空），所以这条信息不是存在 NVR 里的字段，而是运行时这个自检算出来的。

### 8.3 什么时候会「看到」这句话

只有 SETUP 显示「Configuration Errors Found」那一页时才看得到；而那一页仅在配置记录无效（NVR 空白、时钟掉电）时出现。跑一次 SETUP 存好配置后，冷启动不再出现该页 —— 但**自检本身仍然每次都失败**，只是没人去看。

### 8.4 为什么 XT-IDE 也过不了（实测，不是推断）

先纠正上一版的错误结论：早先那次「写没落地」的检查跑在一个**根本没挂控制器**的虚拟机上（配置里 `hdc_1`/`hdd_01` 的字符串替换没生效），所以不能作为证据。

在**确认挂上 XT-IDE 且卡工作正常**的环境里重测（`vectra-hdd2`）：

| 观察项 | 结果 | 说明 |
|---|---|---|
| 选项 ROM | `C8000` = `55AA` | 卡在 |
| `0040:0075` | **1** | BIOS 认到一块盘 |
| XT-IDE 自检菜单 | `A»FDD [A] C»HDD [C]` | 卡自己认到软驱与硬盘 |
| DOS 下 INT 13h | 钩子 `0070:0E78`，链上原处理程序 = **`C800:1452`** | 请求最终会走到卡的 handler |
| **`INT 13h AH=2, DL=80h, CHS 0/0/1`** | **`AX = 0001`（AH=1，无效功能/参数）** | 实测，用 DEBUG 直接执行 |
| 整盘 20.4 MB 前后比对 | **0 字节变化** | 写确实没有发生 |
| SETUP 错误页 | 仍报 `DISK C: FAILED INITIALIZATION` | 与自检失败一致 |

也就是说：**卡在、盘在、DOS 的 INT 13h 链也指向卡的 handler，但 HP BIOS 要的那个调用（`CHS 0/0/1`）拿回来的是 `AH=1`。** 自检在第一步（写）就废了，于是 `AX=8200h`。

`AH=1` 究竟是卡拒绝还是别的环节拒绝，尚未定位。两个待验候选：

1. **调用时机**：HP BIOS 是在选项 ROM 扫描循环里、`cli` 状态下、`ES=F000` 指针下发起调用；此时 XT-IDE 的驱动器表可能还没进入它自己认可的状态；
2. **目标扇区**：`CHS 0/0/1` 就是 MBR 所在扇区，XT-IDE 可能对写引导扇区有条件限制（`AH=8` 与 `CHS 0/0/2` 的对照实验还没跑通，DEBUG 汇编环节被打断）。

无论哪条，结论一致：**这条自检要过，必须有一个「按 HP 语义应答 0/0/1 写读」的选项 ROM** —— 也就是 45816A 的固件，或按同样语义自己写一段。

## 9. 别的 HP 硬盘固件能搜到吗（2026-11-01 再查）

| 目标 | 结果 |
|---|---|
| **45816A / 45817A 卡 ROM** | ❌ 仍然没有。本轮又过了一遍：bitsavers `/bits/HP/` 全树、vtda.org `/bits/ROMs/HP/`、86Box roms、archive.org、vcfed 78146、以及部件号搜索（`45816-80001` 等） |
| **HP 9133 / 9134 磁盘机控制器** | ✅ 有：bitsavers `/bits/HP/disc_firmware/`，4 个 16 KB bin（`09133-89106_9134.bin`、`09133-89110_9133.bin`、`09133-89206_9134.bin`、`09133-89210_9133.bin`），MAME 已据此实现 `hp9133`（PR #12561） |
| **HP 9153 / 9154** | ⚠️ 只有固件升级套件编号 `PN09153-89902`（服务手册提到），没有公开 bin |
| **vtda.org `/bits/ROMs/HP/`** | 只有 `HPIL_SCSI_27256.bin`（32 KB），与硬盘无关 |

**为什么 9133 的固件不能拿来顶 45816A**：9133 是 HP-IB 总线、CS/80 命令集的独立盘机，主机侧走 HP-IB；45816A 是 PC 总线卡，主机侧只有「控制/状态 + 双向 FIFO」两个寄存器，命令字私有。两者虽然都是 6809 智能子系统，但**总线接口和命令集都不同**，固件无法移植，只能当 HP 磁盘代码风格的参考。

**真正有用的收获在本地**：`docs/hp-vectra/manuals/vol2_full.pdf`（*Vectra System BIOS Technical Reference Manual* Volume 2，514 页，带 OCR 文字层）第 8 章把卡 ROM 的契约写清楚了 —— 这等于给了写 HLE 选项 ROM 的规格书（见 §10）。

## 10. 选项 ROM 契约（Vol 2 §8.1.5 原文要点）

1. SYSGEN 先把 `INT 13h` 指向**软驱**驱动（在 Processor Extension Card 的 ROM BIOS 里）；
2. 然后在 **`C8000h–DFFFFh`** 扫描选项 ROM，发现硬盘 ROM 后调用它的初始化入口；
3. 卡 ROM 初始化必须调 **`F13_GET_HPARMS (AH=08h)`**、`DL=80h` 查询当前已链接的硬盘数 `n`（没有其它硬盘时返回坏命令错，`n` 按 0 处理）；
4. 自己的起始设备号 = **`80h + n`**；
5. 若自己是第一块：把 `INT 13h`（`0:04Ch`）里的软驱入口搬到 **`INT 40h`（`0:100h`）**；否则把前一个硬盘驱动的入口存进自己的 RAM；
6. 自己的入口写进 `INT 13h`。之后 `DL < 80h` 的请求由硬盘代码用 **`INT 40h`** 转给软驱；
7. 初始化完成后：主 8259 使能 STD-Slave 控制器中断，从 8259 关掉 IRQ14/15；
8. **在 CMOS 里置位/清除「C:（80h）可作为启动盘」的诊断位**。

手册还特意注明：IBM-PC/XT 那类标准硬盘卡不按这套链机制实现，只要 HP 卡的内存地址配得比它们高，两套就能共存 —— 这正好解释了为什么 XT-IDE 插上去不冲突、却也过不了 HP 的检查。

## 11. `DISK C: FAILED INITIALIZATION` 的确切定义（已闭环）

Vol 2 **附录 C，表 C.6 `CMOS_DIAGNOSTIC_STATUS`（CMOS 地址 `0Eh`）**：

| 位 | 含义 | SETUP 错误页对应行 |
|---|---|---|
| 7 | Power to RTC failed | `CLOCK CHIP LOST POWER` |
| 6 | Bad industry standard CMOS checksum | `CONFIGURATION RECORD BAD` |
| 5 | Configuration inconsistency | `INCORRECT CONFIGURATION INFORMATION` |
| 4 | Memory size does not match | `MEMORY SIZE MISCOMPARE` |
| **3** | **Hard disc failed initialization** | **`DISK C: FAILED INITIALIZATION`** |
| 2 | Invalid CMOS | —— |
| 1–0 | Reserved | —— |

**实测闭环**：删掉 NVR → 冷启动一次（不进 SETUP）→ 退出后读 NVR 第 `0Eh` 字节：

```
CMOS[0Eh] = 0xFF   →  bit7 时钟掉电, bit6 校验错, bit5 配置不一致,
                       bit4 内存不符, bit3 硬盘初始化失败, bit2 无效 CMOS
前 24 字节: 31 ff 00 ff 00 ff 01 01 01 80 26 02 7f 80 ff 00 ff ff ff ff ff 7c 02 ff
```

所以那行字**不是**对硬件的实时探测，而是 POST 把 `CMOS[0Eh]` 的 bit3 置起来、SETUP 再按位翻译成人话。跑一次 SETUP 保存配置后该字节被清 0，错误页随之消失 —— 与 §7 的观察一致。

## 12. HP 9133/9134 与 45816A 的结构对照（2026-11-01）

原件已下载到 `~/documents/86box/docs/hp-vectra/manuals/hp9133/`（不在仓库里）：

| 文件 | 内容 |
|---|---|
| `9133_Roadrunner_III_Design_Notes.pdf` | 36 页，Roadrunner III（9133D/9134D）概述、SUBSET/80 协议、跳线、自检流程 |
| `5957-6560_9133_9134_D_H_L_Service_Apr88.pdf` | 126 页，9133/9134 D/H/L 服务手册 |
| `9133H_SchematicsByTonyDuell.pdf` | 42 页原理图（扫描件，无文字层） |

### 12.1 9133 侧的事实（原文摘录）

- CPU 是 **6809**（服务手册 "6809 is bad. Replace the 6809."）。
- 有**处理器 RAM** 与 **2K × 8 字节缓冲 RAM**（"the 2K by 8 byte buffer RAM chip"），"X 8 static ram, this combination acts as a **FIFO type arrangement**"。
- 硬盘侧是 **WD 控制器芯片** + DP8460 数据分离/锁相环。
- 主机侧是 **HP-IB**，协议 **SUBSET/80（SS/80）**；设计笔记写明"9133D 是双面 Sony 软驱 + 15 MB Seagate 硬盘"，9133A/B/V/XV 用 AMIGO，D/H/L 用 SS/80。
- **开机自检顺序**：处理器 → ROM → HP-IB 芯片 → 处理器 RAM → 缓冲 RAM → 两个驱动器；其中"硬盘测试包括读写扇区"（"The hard disc test includes reading and writing sectors"）。

### 12.2 与 45816A 的对照

| 项 | 9133/9134 | 45816A |
|---|---|---|
| CPU | 6809 | **6809** |
| 缓冲/数据 RAM | 2 KB（FIFO 式排列） | **2 KB**（8 KB 窗口的后 2 KB） |
| 固件位置 | ROM | 6 KB ROM（8 KB 窗口的前 6 KB） |
| 盘控制器 | WD 控制器 + DP8460 | 未公开（手册只说是"智能子系统"） |
| 主机总线 | HP-IB（IEEE-488） | **PC 总线，`1F0h`/`320h`** |
| 主机侧寄存器 | HP-IB 芯片（talker/listener） | **控制/状态寄存器 + 双向 FIFO** |
| 命令集 | AMIGO / SUBSET-80（公开、有文档） | **私有，手册只有"两位表示协议相位"一句** |
| 开机自检含读写扇区 | ✅ 明确写了 | ✅ POST 那段代码（§8）正是写读比较 |

### 12.3 结论

1. **同一条技术线**：9133 与 45816A 都是「6809 + 2 KB 缓冲 RAM + 盘控制器」的 HP 自研磁盘子系统；45816A 相当于把 9133 的控制器主机接口从 HP-IB 换成 PC 总线上的「两个寄存器 + FIFO」。
2. **自检哲学一致**：两边都以「真实写一个扇区再读回来比较」作为硬盘初始化是否成功的判据 —— 这印证了 §8 那段 POST 代码不是"看卡在不在"，而是在要求卡完成一次真实扇区读写，并把结果写进 `CMOS[0Eh]` bit3。
3. **协议仍不可移植**：9133 的 SS/80 是 HP-IB 上的 talker/listener 命令块模型，45816A 是 FIFO 上的私有命令字。手册那句"两位表示协议相位"暗示它沿用了 SS/80 的**相位**概念（命令 / 数据 / 状态 / 结束），但**没有任何文档或固件能确认具体编码**。
4. 因此 9133 的固件与文档只能用来**印证设计谱系和自检思路**，不能拿来实现 45816A 的寄存器语义。

### 12.4 那四个 16 KB 固件镜像到底是什么（已核实）

bitsavers `9133_9134.txt` 原文：

```
9133/9134
1818-3604 27128
9133 09133-89110 09133-89210
9134 09133-89106 09133-89206
68B09
WD2793 floppy
WD2010 hd
```

- ROM 芯片：HP 件号 **1818-3604**，是 **27128**（16 KB）EPROM；CPU 是 **68B09**（不是 6809 原版）；软驱控制器 **WD2793**，硬盘控制器 **WD2010**。
- **两片不是偶奇交错**（我试过 interleave，还原不出合理向量），而是 **32 KB 代码空间的两个半区**：MAME `src/devices/bus/ieee488/hp9133.cpp` 里

  ```
  ROM_REGION(0x8000, "cpu", 0)
  ROM_LOAD("09133-89110_9133.bin", 0x0000, 0x4000, SHA1(aeeae063fa43…))
  ROM_LOAD("09133-89210_9133.bin", 0x4000, 0x4000, SHA1(61766b1f6447…))
  ```

  与本地下载的四个 bin 的 SHA1 完全一致（89110 = `aeeae063fa43`、89210 = `61766b1f6447`）。
- MAME 里它是 **IEEE-488（HP-IB）总线设备**，配 MC6809 @ 8 MHz + WD2010 @ 5 MHz；MAME 目前只做了 9133 的 ROM set，没有 9134。
- 所以这份固件的"用户"是**盘机自己**（真机或模拟的 9133/9134），它面向的主机是 HP 85/86/87、HP 9000 200/300 这类 HP-IB 主机，**不是 PC**；与 45816A 的 6 KB 选项 ROM 是两套完全不同的固件。
- 附带：**WD2010 我们在 VAXmate 那条线里已经实现过**（`src/disk/hdc_st506_wd10.c` 的 WD2010 变体），所以 9133 硬盘侧对我们不是黑盒。

### 12.5 这些文档里有寄存器记录吗

**没有任何一份给出寄存器名 / 地址 / 位定义。** 逐个看：

| 文档 | 关于寄存器写了什么 |
|---|---|
| 9133 设计笔记 | 自检清单里只有「HP-IB 芯片的**两个**寄存器写入并校验」「FOC 芯片的两个寄存器」「**WD1010 的所有读写寄存器**」「WD1100 的四个寄存器写入各种图案」——只有动作，没有地址和位定义 |
| 9133 D/H/L 服务手册 | 同上（把 FOC 改称 HOC = Hard Disc Controller），仍无地址 |
| **9133H 原理图（42 页，手绘）** | **有地址译码电路，但没有寄存器表**。第 2 页 74LS139（U18a）用 A15/A14 产生四个片选：`/IO` `0000–3FFF`、`/RAMCS` `4000–7FFF`（6116，2K×8，窗口内镜像）、`/ROMLCS` `8000–BFFF`（U9 27128）、`/ROMHCS` `C000–FFFF`（U13 27128）。HP-IB 芯片与 WD2010 只可能在 `/IO` 区，二级译码在别的页，且图上一个寄存器名都没有 |
| 45816A 手册第 9 章 | 只有「控制（写）/ 状态（读）+ 双向 FIFO 数据口」和「状态寄存器两位表示协议相位」，**没有口地址以外的任何寄存器信息**，位定义完全没有 |

顺带一个交叉印证：原理图给出的两片 27128 落位（`8000–BFFF` / `C000–FFFF`）与 MAME `hp9133` 的 `ROM_REGION(0x8000)` 把两个 16 KB 分别放在 `0x0000` / `0x4000` **完全吻合**；而 U4 那颗 **6116（2K×8）** 正是手册里说的"2 KB 缓冲 RAM"。

结论：9133 这边只能从**电路译码**反推地址窗口，寄存器语义要读固件；45816A 那边连窗口都只有手册的一句话。
