# HP 45981A Multi-Mode Video Adapter —— 86Box 实现进度

**文件**：`src/video/vid_hp45981a.c`（CGA 派生卡，复用 `vid_cga.c` 的 CRTC / 渲染 / 时序核心）
**设备名**：`hp45981a`（配置项 `gfxcard = hp45981a`）
**状态**：步骤 1（端口面）+ 步骤 2（32 KB 显存 / 8 页）已完成并跑通整机；步骤 3（400 线）未做。

## 1. 已实现的端口面

| 端口 | 方向 | 含义 | 由谁处理 |
|---|---|---|---|
| `3D0`/`3D2`/`3D4`/`3D6` | 写 | MC6845 索引寄存器（四处镜像） | `cga_out()`（内部 `addr & 0xFF9 \| 4` 归一） |
| `3D1`/`3D3`/`3D5`/`3D7` | 读写 | MC6845 数据寄存器（四处镜像） | `cga_out()` / `cga_in()` |
| `3D8` | 写 | 模式控制（6 位，同 CGA） | `cga_out()` |
| `3D9` | 写 | 颜色选择 | `cga_out()` |
| `3DA` | 读 | 状态（回扫 / 垂直同步） | `cga_in()` |
| `3DB`/`3DC` | 读 | 光笔锁存 | `cga_in()`（本卡不使用） |
| **`3DE`** | **写** | **扩展控制寄存器（6 位）** | `hp45981a_set_ext_ctrl()` |
| **`3DF`** | **读** | **Board ID 寄存器，固定返回 `41h`**（手册「Board ID Register」） | `hp45981a_in()` |

### `3DA` 状态位的 HP 专有含义（手册 Table 7.8）

| 位 | 含义 |
|---|---|
| 4 | 监视器类型：`0` = 25 kHz，`1` = 15 kHz（由 W2 跳线决定，**与 `3DE` bit0 无关**） |
| 5 | `0` = 接彩色适配器，`1` = 未接 |
| 6/7 | 诊断用 |

本模型默认 15 kHz（`3DA` bit4 = 1）；设 `HP45981A_25KHZ=1` 则模拟 W2 跳到 25 kHz（bit4 = 0）。

`3DE` 位定义（手册第 7 章）：

| 位 | 含义 | 实现 |
|---|---|---|
| 0 | `0` = 200 线，`1` = 400 线 | **切换字符时钟（14.318 MHz → 22.44 MHz）并启用 16 行字符单元渲染** |
| 1 | 下划线使能 | 只锁存（属性渲染未实现） |
| 2 | 字体 `0` = 标准，`1` = HP Roman-8 | **切换 `cga.font16`** |
| 3 | 显存禁止响应 | **CPU 读写一律丢弃 / 返回 `0xFF`** → 屏幕空白 |
| 4 | `0` = 16K 地址空间，`1` = 32K | **切换 `cga.vram_mask`（0x3FFF / 0x7FFF）** |
| 5 | 页选择（仅图形模式） | 只锁存（图形翻页未用） |

## 2. 显存

- 32 KB，映射 `B8000–BFFFF`，通过 `hp45981a_read/write` 包一层再交给 `cga_write/read`。
- **16K 模式**：地址按 `& 0x3FFF` 回绕，CPU 只看到前 16 KB（手册 Table 7.6「前 16K 可用、32K 内回绕」）。
- **32K 模式**：`& 0x7FFF`，整块可见。
- **字符模式翻页靠 6845 起始地址**（R12/R13），不靠 `3DE` bit5：80×25 一页 2000 字 = 4000 字节，八页正好填满 32 KB。渲染路径直接沿用 CGA 的 `memaddr`，因此翻页是免费的。

为支持 32 KB，`vid_cga.c` 里原先写死的 `DEVICE_VRAM_MASK` 改成 `cga_t.vram_mask`（新增字段），并加了 `cga_vram_mask()` 兜底：NCR、Olivetti OGC、PC1512 等不调用 `cga_init()` 的派生卡仍按 0x3FFF 走，行为不变。

## 3. 字符 ROM

- 卡在初始化时尝试加载 `roms/machines/hpvectra/45981a_chargen.bin`（4096 字节，256 字符 × 16 行）。
- 加载成功才允许 `3DE` bit2 切到 HP 字体；文件缺失则始终用 IBM CGA 字体（不报错，不影响启动）。
- 200 线文本模式下用该字模的**第 1–8 行**（`cga_glyph_row()`，注释在函数上）。

## 3.1 400 线（`3DE` bit0）

主振 **22.440 MHz**、字符时钟 = 8 点 = **2.805 MHz**、行频 **25 kHz**、场频 **60 Hz**（手册 §7「Clock Cycle」+ Figure 20 的 W2 跳线：25 kHz 监视器配 60 Hz，15 kHz 配 50 Hz）。

实现方式（不做垂直寄存器翻译）：

- `3DE` bit0 置位时把 `cga.clk` 从 `CGACONST`（14.318 MHz/8）切到 22.44 MHz/8，行/场时长按 CRTC 重新计算；
- 字符单元按 CRTC **R9** 判断：`R9 > 7` → 用 16 行字模的**整格**（行 0–15），否则用行 1–8；
- 行计数器上限从 360 提到 512（400 行 + 消隐）；
- 典型 400 线文本的 CRTC：`R0=6Fh`(112 字符) `R1=4Fh`(80 列) `R4=19h` `R6=19h` `R9=0Fh` → 26 字符行 × 16 = 416 行，416 × 39.9 µs ≈ **60.2 Hz**。

### 3.3 CRTC 翻译（部分实现：按手册模式表复现，ROM 本身未还原）

手册 Table 7.7「Initial Chip Values」同时给出每种模式的 **15 kHz 值**与 **25 kHz 值**，这些 15 kHz 值就是 IBM CGA 标准集（`71 50 5A 0A 1F 06 19 1C 02 07 06 07` = 80×25 文本），正好可以交叉验证转录无误：

| 模式 | 15 kHz（R0–R11） | 25 kHz（R0–R11） |
|---|---|---|
| 80×25 60 Hz | `71 50 5A 0A 1F 06 19 1C 02 07 06 07` | `6D 50 57 0A 19 09 19 19 00 0F 0E 0F` |
| 40×25 60 Hz | `38 28 2D 0A 1F 06 19 1C 02 07 06 07` | `36 28 2C 0A 19 09 19 19 00 0F 0E 0F` |
| 320×200 / 640×200 60 Hz | `38 28 2D 0A 7F 06 64 70 02 01 06 07` | `36 28 2B 0A 69 01 64 66 00 03 0E 0F` |

实现的语义：当 W2 选 25 kHz 监视器、且写入值 < `80h` 时，卡在每次 CRTC 数据写入后比对 R0–R11；命中上表某一组 15 kHz 值就整组替换为对应的 25 kHz 值（并把光标寄存器改成 `0E/0F`）。未列出的值原样通过。

**为什么没有还原 ROM 本体**：手册说翻译地址由「索引低 4 位 + 数据」组成（看似 `ROM[寄存器][值]`），但模式表自证它不是——**同一个输入 `06h` 在寄存器 5 上，文本模式翻译成 `09h`、图形模式翻译成 `01h`**。所以 ROM 不是简单的 (寄存器, 值) 查表，光凭手册无法还原，只能用「整组模式替换」近似。

⚠️ **未实现：翻译 ROM 本体**。手册 §「Translation」说明：接 25 kHz 监视器时，卡上有一块翻译 ROM 把程序按 15 kHz 写的 CRTC 值（<80h）翻译成 25 kHz 的值；写 `80h–FFh` 可绕过翻译。这块 ROM 同样没有 dump，所以本模型**不会**把 200 线的 CRTC 值自动翻倍——400 线要由软件自己按 16 行单元编程（或用下面的测试钩子）。

### 3.2 真机软件的证据：Diagraph 2000 3.5

WinWorld 的 *Diagraph 2000 3.5*（1986，5.25" 360K）是目前唯一找到的、真正访问 `3DE`/`3DF` 的软件（其说明写着支持 HP 45981A/45984A/45985A）。`DIAGRAPH.EXE`（267 172 字节）里：

```
2C43A: ba df 03      mov  dx,3DF
       ec            in   al,dx
       3c ff         cmp  al,0FFh
       75 2b         jne  2C46D
       ...              ; 读回 FFh ⇒ 再试 A0000 段可写性（写 ABCDh 标记再读）
2C46D: 3c 41         cmp  al,41h     ← 返回 ZF=1 表示「检测到 45981A」
       c3            ret
```

```
2BF0F: ba d8 03      mov  dx,3D8
       b0 16         mov  al,16h     ; 640x200 图形
       ee            out  dx,al
2BF15: ba de 03      mov  dx,3DE
       b0 08         mov  al,08h     ; ← 3DE bit3 = 禁止显存响应
       ee            out  dx,al
2BF1B: ...                          ; 随后重编程 CRTC，再用 3DE=00h 放开
```

结论：
- **`3DF` 是 Board ID 寄存器**（`41h`），Diagraph 靠它识别这块卡 —— 已按此实现；
- `3DE` bit3（显存禁止）确实是真机软件用法：**重编程 CRTC 前后掐掉显存访问**；
- Diagraph 只走 CGA 兼容路径，**从不置 bit0（400 线）或 bit2（HP 字体）**，写过的值只有 `08h` 与 `00h`。
